# PLACE_HOLDER

## Участник № 2. Генерация Teacher и личный запуск A123

Три модели решают одни и те же английские математические задачи. Затем Student обучается на ответах Teacher A с seed 123. Каждый этап выполняется локально. Для CPU-версии подходят 64-битная Windows и CPython 3.11–3.13.

| Роль | Модель | Режим |
| --- | --- | --- |
| Teacher A | Qwen2.5-1.5B-Instruct | GGUF Q4_K_M |
| Teacher B | Qwen2.5-3B-Instruct | GGUF Q4_K_M |
| Teacher C | Qwen2.5-7B-Instruct | GGUF Q4_K_M |
| Student A123 и её baseline | Qwen2.5-0.5B-Instruct | один исходный checkpoint, LoRA для A123 |

### Запуск на Windows

Откройте **run-member02.cmd** двойным щелчком. Файл создаёт окружение в папке проекта, проверяет входные данные, ставит CPU-сборки и запускает пилот, затем полный эксперимент. Большие модели загружаются по очереди в локальный кэш. При первой установке нужен интернет. Публичные веса доступны без HF-токена.

Входной файл из пункта 1 — **data/project_data.zip**. Скрипт также ищет его рядом с собой, в папке «Загрузки» и в её подпапке «Telegram Desktop». Если команда уже распаковала исходный архив, отдельным Python-командам можно передать путь к папке через `--data`.

```bat
run-member02.cmd pilot
run-member02.cmd full
```

Первая команда выполняет только пилот, вторая — только полный эксперимент. Для каждого этапа сначала получается датасет A, затем обучается и проверяется личный адаптер, после этого генерируются B и C. Закрытие окна останавливает работу. При повторном запуске готовые ответы используются снова, SFT продолжает работу с последнего полного checkpoint. Первый запуск может быть долгим на CPU. Прогресс генерации виден в окне и в `runs/rows/`.

### Данные и протокол

| Этап | Train | Validation | Test |
| --- | ---: | ---: | ---: |
| Пилот, первые строки исходных разбиений | 100 | 30 | 30 |
| Полный эксперимент | 1 000 | 150 | 200 |

Исходные JSONL содержат `id`, `question`, `reference_answer`. [Общий конфиг](configs/teachers.json) фиксирует SHA-256 разбиений, ревизии и SHA-256 весов, английскую инструкцию и параметры генерации. Веса всех трёх Teacher квантованы одинаковым способом для работы на ноутбуке. Этот режим нужно указывать при сравнении результатов команды. Сам архив хранится у участников.

Каждая Teacher получает только инструкцию и условие. Для всех используется один шаблон Qwen ChatML, жадное декодирование и лимит 192 новых токена. Генерация запускается только для train. Эталон подключается после получения ответа. При проверке ожидается единственная заключительная строка `#### число`. Допускаются знак, десятичная точка и запятые между группами тысяч. Ошибки формата входят в знаменатель accuracy. Выход по лимиту токенов учитывается отдельно.

### Формат для остальных участников

`runs/full/teacher_A.jsonl`, `teacher_B.jsonl` и `teacher_C.jsonl` содержат по одной записи на исходную задачу в исходном порядке. Буква в имени обозначает Teacher. Поля перечислены ниже.

| Поля | Содержание |
| --- | --- |
| `prompt_id`, `prompt` | Исходный идентификатор и полный текст задачи |
| `teacher_id`, `generation_config` | A, B или C, ревизия модели, файлы весов, шаблон и настройки |
| `response`, `reference_answer` | Ответ модели и эталон из исходного файла |
| `extracted_answer`, `is_correct` | Число в виде строки либо `null`, флаг точного числового совпадения |
| `response_tokens`, `finish_reason`, `generation_seconds` | Длина по счётчику движка, причина остановки и время генерации ответа |

Файлы `teacher_*.metrics.json` содержат число верных ответов, accuracy, долю ошибок формата, статистику длин и суммарное время генерации. Исходные строки с ошибками Teacher сохраняются для общего сравнения при одинаковом объёме обучения. Сборка итогового JSONL проверяет полноту, порядок и соответствие конфигурации.

### Личный эксперимент A123

[Конфиг участника](configs/A123.json) фиксирует seed 123, две эпохи, LoRA rank 8, alpha 16, learning rate 0.0002, эффективный батч 16 и длину последовательности до 512 токенов. Параметры обновляются только у LoRA. В обучающем loss учитываются текст assistant и завершение ответа. При превышении длины сохраняются полное условие и конец ответа. Validation loss считается отдельно на целевой строке с эталонным числом. Test открывается для генерации предсказаний после обучения.

Обе версии Student отвечают на одинаковый test с одинаковыми настройками. Для baseline у той же базовой модели отключается адаптер. `delta_pp` — разность accuracy в процентных пунктах.

| Путь внутри `runs/full/A123/` | Результат |
| --- | --- |
| `adapter/` | Веса и конфигурация LoRA, train/validation loss, шаги и статистика обучения |
| `run_config.json`, `training_attempts.jsonl` | Ревизия Student, версии, устройство, seed и журнал попыток |
| `baseline.predictions.jsonl`, `student.predictions.jsonl` | Предсказания обеих моделей и проверка каждой задачи |
| `metrics.json`, `notes.md` | Метрики, изменение к baseline и краткая заметка по фактическим результатам |

Пилот сохраняется отдельно в `runs/pilot/`. Датасеты, адаптер и результаты появляются после вычислений. Для личного журнала участник указывает дату своего запуска и ссылку на его результаты.

### Запуск по этапам

После установки зависимостей в активированном окружении:

```bash
python generate.py --stage full --teacher A
python run_a123.py --stage full --device cpu
python generate.py --stage full --teacher B --teacher C
python generate.py --stage full --assemble
python -m unittest discover -s tests -v
```

Переменная `QWEN_GGUF_DIR` позволяет брать официальные файлы Teacher с диска. Имена и контрольные суммы приведены в общем конфиге. Для установленного заранее Student поддерживается стандартный кэш Hugging Face. Для передачи соседнему участнику достаточно итогового JSONL и соответствующего файла метрик.

Исходные карточки моделей: [Teacher A](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF), [Teacher B](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF), [Teacher C](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct-GGUF), [Student](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct).
