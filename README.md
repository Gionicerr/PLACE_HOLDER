# PLACE_HOLDER

**Результаты обучения Student.** [Актуальные адаптеры A42, B42 и C42](results/README.md).

## Готовые данные Teacher

[Ответы Teacher A, B и C](data/teachers/README.md) опубликованы для пилота на 100 задачах и полного набора на 1 000 задачах. Рядом сохранены исходные ответы, метрики, списки общих ID и контрольные суммы. [Исходный архив задач](data/project_data.zip) содержит согласованные train, validation и test.

Для C42 и C123 доступны [полный набор Teacher C](data/teachers/full/sft/teacher_C.jsonl) и [пилот Teacher C](data/teachers/pilot/sft/teacher_C.jsonl). Seed задаётся при обучении Student.

## Общее обучение Student

Все участники запускают [train.py](train.py) с одним исходным checkpoint Student. Для каждого эксперимента укажи файл ответов своего Teacher, seed и отдельную папку результатов.

Установи зависимости в отдельное окружение Python 3.11 или 3.12. Первый запуск требует доступа к Hugging Face для загрузки базовой модели.

```bash
python -m pip install -r requirements.txt
```

Обучающий JSONL содержит непустые строки `prompt` и `response`. Дополнительные поля, например `prompt_id`, можно сохранить. Используй согласованные в команде наборы SFT с одинаковыми ID задач у всех Teacher.

```bash
python train.py \
  --train-file data/teachers/full/sft/teacher_B.jsonl \
  --model Qwen/Qwen2.5-0.5B-Instruct \
  --revision 7ae557604adf67be50417f59c2c2f167def9a775 \
  --seed 42 \
  --output-dir runs/B42/full
```

По умолчанию используются две эпохи, LoRA rank 8 и alpha 16, learning rate `2e-4` и длина последовательности до 512 токенов. На одном устройстве эффективный размер батча равен 16. Скрипт применяет шаблон диалога модели и считает loss по ответу ассистента. В папке запуска появляются `adapter/`, `run_config.json`, `run_results.json` и `trainer_state.json`.

Для пробного запуска возьми пилотный JSONL, добавь `--max-steps 1` и выбери новую папку результатов. Для расчёта validation loss передай `--validation-file` с теми же полями. По протоколу A123/B42 промпт валидации содержит задачу и общую инструкцию, а `response` содержит `#### ` и эталонное число из validation. Тестовую выборку используй только на этапе итоговой оценки.

Файлы Teacher B и команда для точного повтора B42 с валидацией есть в [пакете B42](https://github.com/Gionicerr/PLACE_HOLDER/tree/bae8237b5782fda37563dccb86254858a620e1a1/B42). Адаптер, журнал и инструкция по передаче на оценку лежат в [results/B42](results/B42).

## Участник № 2. Генерация Teacher и личный запуск A123

**Участнику B42** — [скачать пилот и полный набор Teacher B и запустить обучение с seed 42](B42/README.md).

Три модели решают одни и те же английские математические задачи. Затем Student обучается на ответах Teacher A с seed 123. Каждый этап выполняется локально. Для CPU-версии подходят 64-битная Windows и CPython 3.11–3.13.

| Роль | Модель | Режим |
| --- | --- | --- |
| Teacher A | Qwen2.5-1.5B-Instruct | GGUF Q4_K_M |
| Teacher B | Qwen2.5-3B-Instruct | GGUF Q4_K_M |
| Teacher C | Qwen2.5-7B-Instruct | GGUF Q4_K_M |
| Student A123 и её baseline | Qwen2.5-0.5B-Instruct | один исходный checkpoint, LoRA для A123 |

### Запуск на Windows

Откройте **run-member02.cmd** двойным щелчком. Файл создаёт окружение в папке проекта, проверяет входные данные, ставит CPU-сборки и запускает пилот, затем полный эксперимент. Большие модели загружаются по очереди в локальный кэш. При первой установке нужен интернет. Публичные веса доступны без HF-токена.

Входной файл из пункта 1 — **data/project_data.zip**. Скрипт также ищет его рядом с собой, в папке «Загрузки» и в её подпапке «Telegram Desktop». Если команда уже распаковала исходный архив, отдельным Python-командам можно передать путь к папке через `--data`.

```bat
run-member02.cmd pilot
run-member02.cmd full
```

Первая команда выполняет только пилот, вторая — только полный эксперимент. На каждом этапе три Teacher по очереди решают задачи. Затем формируются три сопоставимых файла для общего тренера и запускается A123. Закрытие окна останавливает работу. Повторный запуск использует готовые ответы всех Teacher и завершённый адаптер. Если прервать само SFT до сохранения адаптера, командный тренер начнёт этот этап заново. Первый запуск может быть долгим на CPU. Прогресс генерации виден в окне и в `runs/rows/`.

### Данные и протокол

Для локального воспроизведения **prepare-B42.cmd** устанавливает зависимости Teacher, генерирует пилот на первых 100 задачах, затем полный набор на 1 000. После каждого этапа генератор проверяет общий список ID трёх Teacher. Фактическое число принятых строк указано в соответствующем `sft/alignment.json`.

| Файл для отправки | Проверенный исходный файл |
| --- | --- |
| `runs/B42_to_send/teacher_B_pilot.jsonl` | `runs/pilot/sft/teacher_B.jsonl` |
| `runs/B42_to_send/teacher_B_full.jsonl` | `runs/full/sft/teacher_B.jsonl` |

| Этап | Train | Validation | Test |
| --- | ---: | ---: | ---: |
| Пилот, первые строки исходных разбиений | 100 | 30 | 30 |
| Полный эксперимент | 1 000 | 150 | 200 |

Исходные JSONL содержат `id`, `question`, `reference_answer`. [Общий конфиг](configs/teachers.json) фиксирует SHA-256 разбиений, ревизии и SHA-256 весов, английскую инструкцию и параметры генерации. Веса всех трёх Teacher квантованы одинаковым способом для работы на ноутбуке. Этот режим нужно указывать при сравнении результатов команды. Архив опубликован в [data/project_data.zip](data/project_data.zip).

Каждая Teacher получает условие с одинаковой инструкцией на английском. Эту строку видит и Student при обучении и оценке. Для всех используется один шаблон Qwen ChatML, жадное декодирование и лимит 192 новых токена. Генерация запускается только для train. Эталон подключается после получения ответа. При проверке ожидается единственная заключительная строка `#### число`. Допускаются знак, десятичная точка и запятые между группами тысяч. Ошибки формата входят в знаменатель accuracy. Выход по лимиту токенов учитывается отдельно.

### Формат для остальных участников

`runs/full/teacher_A.jsonl`, `teacher_B.jsonl` и `teacher_C.jsonl` содержат по одной записи на исходную задачу в исходном порядке. Буква в имени обозначает Teacher. Поля перечислены ниже.

| Поля | Содержание |
| --- | --- |
| `prompt_id`, `question`, `prompt` | Исходный ID, исходное условие и полный пользовательский текст с инструкцией |
| `teacher_id`, `generation_config` | A, B или C, ревизия модели, файлы весов, шаблон и настройки |
| `response`, `reference_answer` | Ответ модели и эталон из исходного файла |
| `extracted_answer`, `is_correct` | Число в виде строки либо `null`, флаг точного числового совпадения |
| `response_tokens`, `finish_reason`, `generation_seconds` | Длина по счётчику движка, причина остановки и время генерации ответа |

Файлы `teacher_*.metrics.json` содержат число верных ответов, accuracy, долю ошибок формата, статистику длин и суммарное время генерации. Все ответы, включая пустые, сохраняются в исходных JSONL и учитываются при оценке Teacher. Командный `train.py` принимает непустые `prompt` и `response`. Если хотя бы одна Teacher вернула пустую строку, задача исключается из входа SFT у всех трёх. Неверные числа и ошибки формата в непустых ответах сохраняются. Файлы `sft/teacher_A.jsonl`, `sft/teacher_B.jsonl` и `sft/teacher_C.jsonl` имеют одинаковые ID и порядок. Список вошедших и исключённых ID хранится в `sft/alignment.json`.

### Личный эксперимент A123

[Конфиг участника](configs/A123.json) фиксирует seed 123, две эпохи, LoRA rank 8, alpha 16, learning rate 0.0002, эффективный батч 16 и длину последовательности до 512 токенов. Обёртка вызывает общий [train.py](train.py) команды из коммита [4716036](https://github.com/Gionicerr/PLACE_HOLDER/commit/471603698be7955c0b2491454920681279cf1332). LoRA применяется ко всем линейным слоям по правилам общего тренера. В обучающем loss учитывается часть assistant, включая токен конца хода, если он поместился. Длинные последовательности обрезаются справа. Тренер проверяет наличие хотя бы одного целевого токена. Validation loss считается отдельно на целевой строке с эталонным числом. Test открывается для генерации предсказаний после обучения.

Обе версии Student отвечают на одинаковый test с одинаковыми настройками. Для baseline у той же базовой модели отключается адаптер. `delta_pp` — разность accuracy в процентных пунктах.

| Путь внутри `runs/full/A123/` | Результат |
| --- | --- |
| `training/adapter/` | Веса и конфигурация LoRA, токенизатор |
| `training/run_results.json`, `training/trainer_state.json` | Train/validation loss, время, шаги и память CUDA при наличии |
| `experiment.json`, `training/run_config.json`, `training_attempts.jsonl` | Ревизия Student, версии, устройство, seed и журнал попыток |
| `baseline.predictions.jsonl`, `student.predictions.jsonl` | Предсказания обеих моделей и проверка каждой задачи |
| `metrics.json`, `notes.md` | Метрики, изменение к baseline и краткая заметка по фактическим результатам |

Пилот сохраняется отдельно в `runs/pilot/`. Готовые датасеты Teacher опубликованы в [data/teachers](data/teachers/README.md). Адаптер и результаты A123 появляются после выполнения личного обучения и оценки. Для личного журнала участник указывает дату своего запуска и ссылку на его результаты.

### Запуск по этапам

После установки зависимостей в активированном окружении:

```bash
python generate.py --stage full
python run_a123.py --stage full --device cpu
python generate.py --stage full --assemble
python -m unittest discover -s tests -v
```

Переменная `QWEN_GGUF_DIR` позволяет брать официальные файлы Teacher с диска. Имена и контрольные суммы приведены в общем конфиге. Для установленного заранее Student поддерживается стандартный кэш Hugging Face. Остальным участникам для обучения передаётся соответствующий JSONL из `sft/`, для анализа Teacher — полный JSONL и файл метрик.

Исходные карточки моделей: [Teacher A](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF), [Teacher B](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF), [Teacher C](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct-GGUF), [Student](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct).
